## VCS

A **Version Control System (VCS)** is a program or set of programs that tracks changes to a collection of files.

- One goal of a VCS is to recall earlier versions of individual files or of the entire project.
- Another goal is to allow several team members to work on a project at the same time without affecting each other’s work.
- Another name is **Software Configuration Management system**.

## Git

- **Distributed Version Control System**.
- Git is a fast, versatile, highly scalable, free, open-source VCS.
- Its primary author is **Linus Torvalds**, the creator of Linux.

## GitHub

- GitHub is a cloud platform that uses Git as its core technology.

## Git Terminology

- **Working tree**: The set of nested directories and files that contain the project that's being worked on.
- **Repository (repo)**: The directory at the top level of a working tree where Git keeps all the history and metadata for a project.
- **Hash**: A number produced by a hash function that represents the contents of a file or another object as a fixed number of digits.
- **Object**: A Git repo contains four types of objects, each uniquely identified by an SHA-1 hash:
  - Blob Object
  - Tree Object
  - Commit Object
  - Tag
- **Commit**: Committing the changes you have made so that others can eventually see them.
- **Branch**: A named series of linked commits.  
  - The head of the current branch is named `HEAD`.  
  - The default branch is usually called `main` (previously `master`).
- **Remote**: A named reference to another Git repo.

## Commands, Subcommands, and Options

### Configure Git

```bash
git --version
git config --global user.name "<USER_NAME>"
git config --global user.email "<USER_EMAIL>"
git config --list
```

### Set Up Your Git Repo

```bash
mkdir Cats         # Create folder
cd Cats            # Change to the project
git init -b main   # Initialize repo and set default branch
git status         # Show status
ls -a              # List contents of the working tree
```

---

## Basic Git Commands

- `git status` – Displays the state of the working tree.
- `git add` – Stages changes to prepare for a commit.
- `git commit` – Commits the changes.
- `git log` – Shows commit history.
- `git help` – Displays help for Git commands.

## How Do I Commit My Project to GitHub?

### Step 1: Create a GitHub Repository  

*(On GitHub)*

### Step 2: Initialize Git in Your Project

```bash
git init                     # Initialize Git
git add .                    # Add all files to staging
git commit -m "Initial commit: URL Monitor project"
git remote add origin https://github.com/YOUR_USERNAME/webmon.git
git branch -M main           # Rename the branch to 'main'
git push -u origin main      # Push code to GitHub
```

### Following Commits

```bash
git status                   # Check status (optional)
git add .                    # Add all changes to staging
# or
git add path/to/your/file.py # Add specific file
git commit -m "Add health check endpoint to monitor"
git push                     # Push to GitHub
```

## .gitignore File

A `.gitignore` file is super useful in any Git project. It tells Git which files or folders to ignore — meaning they won’t be tracked or pushed to GitHub.
